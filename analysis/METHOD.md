# 诊断与回放方法说明

本目录的分析代码在 `src/`，入口为 `run_analysis.py`，输出报告在
`analysis/report.json`。所有读取仅基于交换包中各时点**已经到达（arrived）**
的事实，不虚构缺失工作量。

## 运行

```sh
python3 -I run_analysis.py data --out analysis/report.json
python3 -I -m unittest discover -s tests -v
```

`-I` 隔离模式避免从数据目录加载任何旁路模块；数据目录与脚本目录分离。

## 口径实现（对应 data-contract.md）

1. **副本与接手分离**：`kind=copy` 只证明副本到达，不进入有效时间线，
   不构成 `site_received` 接手。全量 18 条 copy 均无对应正本。
2. **补录归并**：`supersedes` 指向的原记录降级为证据，补录成为该动作有效记录；
   补录在其 `arrived` 之前不参与值班判断。补录影响的环节不进入常规等待分布，
   其解释变化单列（见下）。
3. **退回**：`kind=returned` 结束本次未经确认的交件，实例归“已明确退回”，
   与“到观察期无回执”“尚未到交件时间”严格分开，不互相混合。
4. **双时间视角**：
   - `arrived`（主口径）：记录可用于值班判断的分钟，用于等待与堵点回放；
   - `earliest/latest`（时钟视角）：只用于检验动作先后能否唯一确定。
     前一动作 `latest <` 后一动作 `earliest` 才把等待归因到单一环节；
     区间重叠意味着来源各自有时钟、可行顺序不唯一，标记 `ambiguous`，
     不把跨环节数字拼到某一环节，也不为同一实例在各环节分别挑最短值。
5. **并行变体**：`first_confirm` 与 `scope_confirm` 属同一并行类，
   共享前置 `site_received`，各自独立计等待；观察顺序与命名顺序相反记
   `parallel_reversed`，仍归并行变体而非新流程。
6. **逾期按学生本人条件核查**：以每位学生的 `eligible_min/due_min` 判定；
   同 `group` 共用动作的去重只在场次效率统计中做一次，不影响个人逾期。

## 真实堵点

- **教学点代收窗口系统性超载**：site 每窗口容量 6，实际每窗口到达 8–10 件，
  11 个工作窗口全部超容量。系统级回放中 site 环节排队 53,754 分钟、6 例窗口耗尽，
  是最大、最确定的堵点。
- **W0 在 V2 下的资格缺口**：V2 把 scope_required 改为 W0/W3，但 W0 教师
  T0/T4 的 skills 仅 `first_confirm`，无 `scope_confirm` 资格。13 个 W0/V2
  实例缺 scope_confirm，其中 12 个在缺必备确认的情况下仍登记（register_bypass）。
- **登记环节**：office 窗口与教师窗口错位 40 分钟，形成稳定的登记前等待。
- 留存缺口：observability 12 条声明中 6 条与日志矛盾（声明 log_missing
  但窗口内存在有效记录），6 条与日志一致（确为窗口内无记录）；分析以日志为准，
  矛盾逐条保留在 `证据索引` 中可追溯。

## 补录如何改变堵点解释

- **E034 / scope_confirm**：原记录 E034-4（arrived 4953）被 E034-6
  （arrived 12800）取代，动作时钟区间 [4885,4905] 其实早于登记。
  旧口径从最后回执倒推会把它当成早就完成；按 arrived 重算，当时值班判断
  长期缺少该事实，属于**执行/留存偏差，不是规则改版的估计变化**。
- **E110 / site_received**：补录 E110-5X（arrived 15040）把收件时钟从
  原记录的 ~14947 修正到 [15006,15010]，晚于 first_confirm 的时钟，
  先后关系不再成立，相关等待标记为归因不清。

## 回放纪律与试行结论

- 容量是“同一窗口内能开始处理的最大值”，接手只给有资格且未超容量的人；
  窗口占满顺延下一窗口，再无可行窗口才判无人可接。
- 历史缺有效记录的步骤，回放不虚构到达，整条标记 `missing_workload`。
- 两个视角分开：
  - **系统视角**：全部实例共用容量账本，评估真实竞争与溢出；
  - **隔离配对视角**：同实例两规则各用独立账本，差异只来自规则本身。
- 启用约束：locked 公示（E102/E106/E109）不得改道；仅 W2 的 P2 为
  `announced`（W0/W1/W3 仅 candidate）。28 个 W2 实例合格，92 个不宜启用。
- 隔离口径下规则本身不缩短单例等待（教学点处理很快，中位仅 15 分钟）；
  系统口径下 teacher 路线消除了 site 超载，可完成回放从 14 升到 20，
  site 排队 53,754 → 0，积压转移到 scope_confirm（700 → 1,917）与
  registered（3,222 → 80），教师窗口无超容量。即收益来自**去除单点超载**，
  代价是确认环节工作量上升，需 T1/T3/T5/T7 的 scope 资格兜底。
- 试行观察（pilot_log）与历史推演严格分开：E117 已观察完成（逾期 25 分钟，
  证据 P01–P05），E118 尚未到交件时间（仅 P06）。
